# Restaurant App

Современный сайт-приложение для ресторана на React, Vite и Tailwind CSS. Проект сделан как универсальный шаблон: название, контакты, цвета, преимущества, отзывы, меню, админские email/телефоны и стартовые данные вынесены в `src/data.js`. По умолчанию проект может работать в демо-режиме, а для общей базы подключается Supabase/PostgreSQL.

## Возможности

- Главная страница с hero-блоком, популярными блюдами, преимуществами и отзывами.
- Меню с категориями, карточками блюд и добавлением в корзину.
- Вход в аккаунт по email и одноразовому коду подтверждения.
- После входа клиент должен добавить телефон в профиле, чтобы ресторан мог уточнять заказы и брони.
- Клиент без входа может смотреть сайт, но не может пользоваться корзиной, заказом и бронированием.
- Администратор определяется автоматически по email или админскому телефону из профиля.
- Страница `/admin/orders` только для админов: полный состав заказа, контакты клиента, адрес, оплата, комментарий, бонусы и смена статуса.
- Корзина с изменением количества, удалением блюд и итоговой суммой.
- Оформление заказа с сохранением в `localStorage` или Supabase.
- Бонусная система: после заказа начисляется 5% от суммы, в следующих заказах можно списать до 30%.
- Бронирование столика с сохранением заявки в `localStorage` или Supabase.
- Профиль клиента: уведомления, история заказов, программа лояльности, личные данные, карты и адреса.
- Мини-админка `/admin`: изменение названия, телефона, адреса, добавление и удаление блюд, изменение цены.
- Опциональная демо-БД: профили, адреса, карты, заказы, статусы, бонусы, меню и брони.
- Адаптивная верстка для телефона, планшета и ПК.

## Запуск

```bash
npm install
npm run dev
```

После запуска Vite покажет локальный адрес, обычно `http://localhost:5173`.

Важно: не открывайте проект через VS Code Live Server или двойным кликом по `index.html`. JSX-файлы должны обрабатываться Vite, иначе браузер покажет ошибку MIME type `text/jsx`.

## Supabase

Проект умеет работать без сервера, но для общей базы данных подготовлен Supabase/PostgreSQL:

- SQL-схема: `database/schema.sql`
- инструкция подключения: `DATABASE_SETUP.md`
- пример переменных окружения: `.env.example`

Локально создайте `.env.local`:

```env
VITE_DB_PROVIDER=supabase
VITE_AUTH_PROVIDER=supabase
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-public-key
VITE_ADMIN_EMAILS=owner@example.com
VITE_ADMIN_PHONES=+37361058107
```

Если `VITE_DB_PROVIDER` не указан, сайт работает через `localStorage`. Если `VITE_AUTH_PROVIDER=demo`, код входа показывается прямо на экране. Если `VITE_AUTH_PROVIDER=supabase`, код отправляется на email через Supabase Auth.

## Публикация

Проект подготовлен для GitHub Pages:

- Vite собирает сайт с `base: './'`.
- Роутинг работает через hash-режим, поэтому страницы не ломаются на статическом хостинге.
- Workflow `.github/workflows/deploy.yml` автоматически собирает `dist` и публикует сайт в GitHub Pages после push в `main`.

Для публикации с Supabase добавьте эти секреты в GitHub Actions:

- `VITE_DB_PROVIDER`
- `VITE_AUTH_PROVIDER`
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`
- `VITE_ADMIN_EMAILS`
- `VITE_ADMIN_PHONES`

## Авторизация

Вход работает по email:

1. Пользователь вводит имя и email.
2. Приложение отправляет код подтверждения на почту через Supabase Auth или показывает демо-код на экране.
3. После ввода кода создается профиль клиента.
4. Для заказа и бронирования клиент должен добавить телефон в разделе "Мой профиль".

Для реальной отправки кода включите Email provider в Supabase: `Authentication` → `Sign In / Providers` → `Email`. В email-шаблоне должен быть OTP token.

## Администраторы

Админка не показывается обычным клиентам. Кнопка "Заказы" появляется только у админского аккаунта.

Админские аккаунты задаются в `src/data.js` или через переменные окружения:

```js
admin: {
  phoneNumbers: ['+37377432554', '+37361058107'],
  emails: ['admin@restaurant.app'],
}
```

```env
VITE_ADMIN_EMAILS=owner@example.com,manager@example.com
VITE_ADMIN_PHONES=+37361058107,+37377432554
```

Email сравнивается в нижнем регистре, телефон сравнивается по цифрам.

## Бонусы

Бонусы привязаны к аккаунту пользователя и сохраняются в `localStorage` или Supabase.

- После каждого заказа начисляется 5% от суммы к оплате.
- В следующем заказе можно списать до 30% суммы заказа.
- Если бонусов нет, в checkout показывается объяснение и прогноз начисления.
- Баланс, ранг и история операций видны на странице `/account`.

## Где менять данные

Основные данные находятся в:

```text
src/data.js
```

Для быстрого брендирования замените:

- `restaurant.name`
- `restaurant.logo`
- `restaurant.phone`
- `restaurant.address`
- `restaurant.email`
- `restaurant.colors`
- `admin.emails`
- `admin.phoneNumbers`
- массив `menuItems`
- блоки `benefits`, `testimonials`, `openingHours`

Изменения, сделанные через админку, сохраняются в браузере или Supabase и имеют приоритет над данными из `data.js`.
