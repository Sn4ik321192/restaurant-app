# Restaurant App

Современный сайт-приложение для ресторана на React, Vite и Tailwind CSS. Проект сделан как универсальный шаблон: название, контакты, цвета, преимущества, отзывы, меню и админские номера вынесены в `src/data.js`. По умолчанию данные сохраняются в `localStorage`, а для общего демо можно подключить Supabase/PostgreSQL.

## Возможности

- Главная страница с hero-блоком, популярными блюдами, преимуществами и отзывами.
- Меню с категориями, карточками блюд и добавлением в корзину.
- Вход в аккаунт по номеру телефона и коду подтверждения.
- Клиент без входа может смотреть сайт, но не может пользоваться корзиной, заказом и бронированием.
- Администратор определяется автоматически по номеру телефона.
- Корзина с изменением количества, удалением блюд и итоговой суммой.
- Оформление заказа с сохранением в `localStorage` или Supabase.
- Бонусная система: после заказа начисляется 5% от суммы, в следующих заказах можно списать до 30%.
- Бронирование столика с сохранением заявки в `localStorage` или Supabase.
- Страницы "О ресторане" и "Контакты".
- Мини-админка: изменение названия, телефона, адреса, добавление и удаление блюд, изменение цены, просмотр заказов и броней.
- Опциональная демо-БД: профили, адреса, карты, заказы, статусы, бонусы, меню и брони.
- Адаптивная верстка для телефона, планшета и ПК.

## Запуск

```bash
npm install
npm run dev
```

После запуска Vite покажет локальный адрес, обычно `http://localhost:5173`.

Важно: не открывайте проект через VS Code Live Server или двойным кликом по `index.html`. JSX-файлы должны обрабатываться Vite, иначе браузер покажет ошибку MIME type `text/jsx`.

## Демо-база данных

Проект умеет работать без сервера, но для общей базы данных подготовлен Supabase/PostgreSQL:

- SQL-схема: `database/schema.sql`
- инструкция подключения: `DATABASE_SETUP.md`
- пример переменных окружения: `.env.example`

Локально создайте `.env.local`:

```env
VITE_DB_PROVIDER=supabase
VITE_SUPABASE_URL=https://your-project.supabase.co
VITE_SUPABASE_ANON_KEY=your-anon-public-key
```

Если эти переменные не указаны, сайт автоматически работает в режиме `localStorage`.

## Публикация

Проект подготовлен для GitHub Pages:

- Vite собирает сайт с `base: './'`.
- Роутинг работает через hash-режим, поэтому страницы не ломаются на статическом хостинге.
- Workflow `.github/workflows/deploy.yml` автоматически собирает `dist` и публикует сайт в GitHub Pages после push в `main`.

Для публикации с Supabase добавьте эти секреты в GitHub Actions:

- `VITE_DB_PROVIDER`
- `VITE_SUPABASE_URL`
- `VITE_SUPABASE_ANON_KEY`

## Авторизация

Вход работает по номеру телефона:

1. Пользователь вводит номер.
2. Приложение генерирует код подтверждения.
3. В демо-версии код показывается на экране.
4. После ввода кода пользователь получает доступ к корзине, заказу и бронированию.

Для реального проекта отправку SMS нужно подключить через backend и SMS-провайдера.

## Администраторы

Админка не показывается обычным клиентам. Кнопка `Admin` появляется только после входа с админского номера.

Админские номера задаются в `src/data.js`:

```js
admin: {
  phoneNumbers: ['37322000000', '37368123456'],
}
```

Номер сравнивается по цифрам, поэтому `+373 22 000 000` и `37322000000` будут считаться одним номером.

## Бонусы

Бонусы привязаны к номеру телефона пользователя и сохраняются в `localStorage` или Supabase.

- После каждого заказа начисляется 5% от суммы к оплате.
- В следующем заказе можно списать до 30% суммы заказа.
- Если бонусов нет, в checkout показывается объяснение и прогноз начисления.
- Баланс виден на странице `/account`.

## Где менять данные

Основные данные находятся в:

```text
src/data.js
```

Для быстрого брендирования замените:

- `restaurant.name`
- `restaurant.logo`
- `restaurant.phone`
- `restaurant.address`
- `restaurant.email`
- `restaurant.colors`
- `admin.phoneNumbers`
- массив `menuItems`
- блоки `benefits`, `testimonials`, `openingHours`

Изменения, сделанные через админку, сохраняются в браузере и имеют приоритет над данными из `data.js`.
